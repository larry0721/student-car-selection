# Demo Intelligence Integration

## Purpose

Phase 3.4A exposes reviewed vehicle evidence alongside the existing recommendation experience. It does not change candidate generation, qualification, scoring, ranking, `RecommendationObject`, or `DecisionReport` behavior.

The runtime path is:

```text
Buyer conversation
  -> confirmed BuyerProfile
  -> existing recommendation engine
  -> RecommendationObject and DecisionReport
  -> existing recommendation results
  -> read-only Vehicle Intelligence panel
```

The panel receives the winning catalog vehicle ID after ranking is complete. It can explain or supplement the recommendation, but it cannot select a vehicle or contribute to a score.

## Deployable Snapshot

The tracked snapshot is `data/demo/goldenVehicleIntelligence.v1.json`. It contains exactly these five reviewed vehicles:

- 2017 Hyundai Accent
- 2016 Toyota Prius
- 2016 Toyota RAV4 FWD
- 2016 Honda CR-V AWD
- 2018 Nissan Leaf

The snapshot is generated by `pnpm generate:demo-intelligence`. The generator reads the current structured golden publications, NHTSA safety report, and qualitative reliability-risk assessments. It retains only sanitized, presentation-safe fields plus source identifiers and attribution.

It intentionally excludes raw API payloads, credentials, local paths, giant evidence arrays, and numerical reliability scores. The source artifacts remain authoritative; the deployable file is a versioned projection for the presentation build.

## User-Facing Rules

- Trusted vehicle facts are shown only when their published provenance status is `verified` or `sourced`.
- Missing, stale, or unsupported fields are not replaced with legacy catalog values.
- NHTSA `NOT_RATED` is displayed as unavailable numeric crash-test evidence, never as zero.
- Reliability is a qualitative concern assessment. It is not a score and does not assert that a vehicle is reliable or unreliable.
- Confidence is presented separately for safety, reliability evidence, and efficiency evidence.
- Missing information is limited to material facts or facts relevant to the buyer's stated priorities.
- A non-golden recommendation remains usable, but its expanded panel states that detailed trusted intelligence has not been added.

## Source Boundaries

The panel uses:

- Existing advisor communication derived from `RecommendationObject` and `DecisionReport` for “Why this fits.”
- Published golden vehicle facts for configuration and efficiency.
- Existing NHTSA safety intelligence for crash-test evidence.
- Existing reliability-risk assessments for qualitative concern evidence.

It does not call external APIs in the browser and does not expose internal publication, claim, compiler, or repository structures in the standard interface.

## Production Migration

The tracked snapshot is deliberately small. Production-scale ingestion remains separate from the web runtime. A future persistent database or server API can replace the snapshot behind the same view-model boundary in `lib/demoVehicleIntelligence.ts`, while preserving the UI and the recommendation-engine boundary.

## Verification

`pnpm test:demo-intelligence` checks the five-record scope, rated and not-rated safety behavior, qualitative reliability framing, source attribution, relevant missing-data disclosure, non-golden fallback, revision integrity, responsive constraints, and ranking immutability.
